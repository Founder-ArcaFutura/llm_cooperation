# Conservative controlled-repair feasibility scan

This is a stopped feasibility experiment, not a production repair or scientific validation. The input is PR #11's effective dataset: 372 production records plus its seven-record overlay. Only the current option text of each unresolved record is considered. The model-generated alternative candidate pools are excluded because their changes to actors, resources, timing, and strategy have not been independently adjudicated. Three narrowly scoped, single-phrase substitutions are enumerated in the engine, and candidates with obvious formatting or known bad-grammar patterns are rejected. This screen is not a general grammar checker or semantic validator. All edits would require independent adjudication.

The serialized 14-case pilot and 124-scenario full scan use the pinned Qwen tokenizer and report candidate counts, final collision checks, selected options and edits, and unresolved outcomes. Both scans returned zero new variants and zero new complete triads. This meets the requested stop condition for this restricted rule set; it does not establish that other, independently reviewed repairs are impossible. No overlay or derived bank files were produced. The optimizer searches combinations jointly and fixes all previously accepted records, but its usefulness on real candidate sets is not established by these zero-candidate results. No hosted inference was used.

Reports record the observed raw source hashes plus newline-normalized hashes for cross-platform comparison. A Windows CRLF checkout changes byte hashes relative to Git's LF blobs; the original PR #11 manifest records the Git-blob overlay hash. An existing test also reads UTF-8 JSON using the platform default encoding. Neither issue was repaired here because the source and prior overlay are protected.

Run `python scripts/repair_controlled_banks_conservative_scan.py` with the pinned tokenizer already cached. Output includes elapsed time, so byte-for-byte identity across runs is not expected. Counts can be recomputed from each report's per-scenario results. This diagnostic does not update the production repair pipeline.
