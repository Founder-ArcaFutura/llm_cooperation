# OLMo 2 1B pretraining-emergence study

This implementation captures the frozen 124-scenario Phase 0B bank independently at five pinned revisions of `allenai/OLMo-2-0425-1B`. It records post-block residuals at the final input token after the trailing `\nDecision:` marker, one prompt per scenario/action, and analyzes each checkpoint independently. It does not compare activation-coordinate directions across checkpoints.

## Checkpoint selection

`olmo_emergence.py select` calls `huggingface_hub.HfApi.list_repo_refs` on the official model repository at execution time. It selects live stage-one refs nearest 0%, 20%, 60%, and 100% of the available stage-one token span, plus the official seed-42 stage-two endpoint (`stage2-ingredient3-step23852-tokens51B`, or `main` only if that endpoint ref is absent and resolves to a distinct commit). The resulting JSON records exact ref, commit SHA, step, cumulative tokens, and stage. It fails closed if five unique official commits cannot be verified. The 37,000-step reconstructed early-training repository is not used.

The endpoint relationship follows AI2's published training description: the 51B-token stage-two run starts from the stage-one endpoint. The selection is therefore one published lineage with a stage boundary, while retaining stage-one steps and stage-two mid-training as distinct labels. The exact refs are generated by the online selection command and are not fabricated in this source tree.

## Prepare plans and run

Run from the repository root with network access to Hugging Face:

```powershell
python -m llm_cooperation.mechanistic.olmo_emergence select --output research/olmo2_emergence/checkpoint_selection.json
python -m llm_cooperation.mechanistic.olmo_emergence prepare-plans --selection research/olmo2_emergence/checkpoint_selection.json --output research/olmo2_emergence/plans
```

Plan preparation fingerprints the scenario bank and creates five separate plans with byte-identical prompts and fixed discovery/domain partitions. Each plan uses the checkpoint's immutable commit SHA as the Transformers revision. No inference is launched by either command.

Before the full study, prepare and run the capture-only technical smoke on the first sampled checkpoint (six independent scenario families):

```powershell
python -m llm_cooperation.mechanistic.olmo_emergence prepare-smoke --selection research/olmo2_emergence/checkpoint_selection.json --output research/olmo2_emergence/technical-smoke
modal run modal_olmo_emergence.py --plans research/olmo2_emergence/technical-smoke --authorize-paid-run --technical-smoke
```

This loads the actual selected OLMo checkpoint, checks tokenizer output lengths and the common marker, captures every layer, and verifies activation shape and finite values. It is a software integration check only. The full run should follow only after this command succeeds.

The complete five-checkpoint inference command is:

```powershell
modal run modal_olmo_emergence.py --plans research/olmo2_emergence/plans --authorize-paid-run
```

To also run the existing full Phase 0 behavioral protocol on all 124 scenarios at each checkpoint, explicitly include its confirmatory split:

```powershell
modal run modal_olmo_emergence.py --plans research/olmo2_emergence/plans --authorize-paid-run --run-behavior --authorize-behavioral-confirmatory
```

Behavioral outputs preserve the raw presentation records and existing Phase 0 analysis reports, including valid-letter rate, position sensitivity, and cooperation rates. Interpret behavior as a separate endpoint; do not call a degenerate choice run evidence for cooperative decision-making. The Modal runner uses an isolated volume and checkpoint-specific directories and a shared Hugging Face cache. It never launches on its own.

## Technical integration test

The OLMo layout integration test uses an OLMo-shaped decoder wrapper with three blocks and verifies per-layer final-token capture, output dimensions, finite values, and hook cleanup. Revision selection is tested against a controlled live-ref fixture. The generalized probe is exercised on a synthetic checkpoint with dimensions different from Qwen. These CPU checks validate software integration only; they are not model evidence and do not establish scientific validity of a completed run.

## Checkpoint-by-layer analysis protocol

For each checkpoint, run `four_strategy_probe.py` independently with the saved plan prompt inventory and manifest. Its partition seed and design are fixed across checkpoints. It reports scenario-centered activations, family/domain-held-out classifiers, per-strategy domain direction alignment and projection margins, word/character-count residualization, unit-vector controls, family/domain-cluster intervals, within-scenario label-permutation nulls, effective rank, and direction geometry. The arrays at different checkpoints are not aligned or directly subtracted.

`analyze_trajectory` places layers on normalized depth `[0, 1]`, retains raw and lexical-adjusted outcomes separately, and reports each strategy's earliest sampled checkpoint satisfying the cross-domain directional criterion. Its one-sided cluster-bootstrap bounds use Bonferroni familywise control over all five checkpoints, all layers, and all four strategies. Both length-adjusted held-out-domain alignment cosine and projection-margin lower bounds must exceed zero. Five samples bound the conclusion to the sampled points; they do not locate an exact emergence time. Probe balanced accuracy and permutation nulls remain complementary diagnostics rather than substitutes for directional consistency.

After retrieving checkpoint analysis JSON files from the Modal volume, create a JSON input list shaped like:

```json
[
  {"checkpoint": {"checkpoint_order": 0, "revision": "...", "training_stage_label": "initialization", "cumulative_tokens_billions": 0}, "analysis_json": ".../four_strategy_report.json"}
]
```

Supply all five rows and run:

```powershell
python -m llm_cooperation.mechanistic.olmo_emergence analyze-trajectory --inputs research/olmo2_emergence/analysis_inputs.json --output research/olmo2_emergence/trajectory
```

The trajectory report does not assert causation or a learned preference for cooperation. It tests whether strategy-related information is linearly accessible in residual streams and how that signal changes alongside separately measured behavioral competence.
