# Extension v2: scientific review and measurement gate

This is a new unreviewed candidate bank. Existing v1 files and completed model outputs are preserved. No new inference was launched. The bank contains 58 physical cases, 1,568 presentations per model and 4,704 planned model-presentation cells.

The benefit block now explains that submitting the trace can trigger an automated check of Morgan's equipment, and Riley may use the trace to check Riley's equipment. Different routing configurations implement different outcomes. This supplies a proposed causal path, not evidence that technicians or reviewers find it plausible; configuration changes are coupled to the benefit manipulation. In particular, the actor-only condition represents submission triggering a check for the sender while the recipient has no use for the copy. Independent reviewers should challenge the causal story, perceived utility, authority, unmentioned costs and technical feasibility. Both domains share a template and are not independent replications.

Each benefit/cost case has binary and three-action versions, all option permutations, both identity assignments and paired actor/recipient perspectives. The additional option requests a ten-minute supervisor review, and its extra explanatory sentence appears only in the three-action context. Choice-set contrasts therefore also change the described options and explanatory wording; they are a sensitivity analysis, not a pure test of action count. Review whether the added alternative is credible or attractive enough to be meaningful. Existing removal/replacement cases remain separate.

The validator checks factor versus target/reference ledgers and the numeric benefit/cost text, return/cost ledgers, risk probabilities, role labels, pairing, option text, permutations and complete rendered presentations. These checks cannot verify causal plausibility, semantic equivalence, or every free-text assertion. Independent blinded reviewers must inspect the full scenario and all outcomes before execution. Freeze review decisions and exact bank hashes before any new inference.

The analyzer produces perspective_contrasts.csv with recipient-preference minus actor-choice send probability for the same condition, identity pair, choice set, and complete option permutations. perspective_interactions.csv gives differences in these contrasts across benefit and cost levels. It reports descriptive conditional probabilities and does not establish a latent preference or produce family-level generalization. Keep binary and three-action results separate.

## Position sensitivity before full evaluation

The existing full v1 records show Mistral selected A in **340/340** unique-max binary presentations; Qwen selected A in 144/341 and OLMo in 199/351. Four-option values were Mistral 1358/3848, Qwen 999/4190, and OLMo 1154/4217. These are observed descriptive counts after excluding exact ties, not proof of the cause of the binary pathology.

After scientific review and explicit approval, the v2 Modal adapter offers a diagnostic subset: all water-domain benefit/cost cases, both choice sets, both perspectives, all identities and option permutations (512 presentations per model). This is a defined design subset, not a spending limit. The same canonical run ID and manifest permit resuming into the full 1,568-presentation run without repeating completed diagnostic rows. Inspect position_diagnostics.csv by model, option count and perspective. The predeclared screen flags A selection in at least 90% of unique maxima when at least 20 unique outcomes are present; ties and sample counts are reported. This is a warning screen, not a validated statistical cutoff or automatic model exclusion. Report raw conditional probabilities and both full-vocabulary and conditional scores. Assess whether each model's binary and three-action measurements vary with action identity, option position and perspective. A model with a failed binary screen should not be interpreted as measuring binary action preference without further evidence; disclose it and analyze sensitivity separately.

The diagnostic is user-launched only after review using the adapter's --approved --diagnostic flags and canonical v2 model run ID. The subsequent full job uses --approved --resume with the same run ID, only after the diagnostic worker stops and the gate is assessed. --resume skips verified rows in that run. Do not launch until the design and review outcomes have been inspected. The new Modal adapter and diagnostic have not been exercised on a GPU.

The v2 tests check factor/ledger and factor/text corruption, direct matched perspective differences and rejection of incomplete pairs. These tests are not human validation.
